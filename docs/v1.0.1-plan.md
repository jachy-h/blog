# v1.0.1 SEO 规范信号修复计划

- 触发问题：Google Search Console 报「重复网页，Google 选择的规范网页与用户指定的不同（Duplicate, Google chose different canonical than user）」
- 目标：全站以 `https://jinyu.cool/` 为唯一规范入口，所有页面的 canonical、og:url、sitemap 提交地址指向同一套 URL

## 排查结论

线上链路本身没有问题：

| 变体 | 结果 |
|---|---|
| `http://jinyu.cool/` | 301 → `https://jinyu.cool/` |
| `https://jinyu.cool/` | 200 |
| `http://www.jinyu.cool/` | 301 → `https://jinyu.cool/` |
| `https://www.jinyu.cool/` | 301 → `https://jinyu.cool/` |
| `https://jinyu.cool/index.html` | 200（GitHub Pages 无法 301，只能靠 canonical 收敛） |

sitemap 内 106 个 URL 逐一抓取，canonical 均自指。真正的问题在 **sitemap 之外、被内部分页链接发现的列表分页页**：

- `/posts/page/2/` … `/posts/page/N/`、`/categories/ai/page/2/` 等页面内容与第 1 页不同，
  却把 canonical 写成了 `/posts/`、`/categories/ai/`。
  Google 判定「用户指定的规范网页」与实际内容不符，于是自行选定规范页 —— 这正是 GSC 该问题的定义。
- 原因：`head.html` 统一用 `.Permalink`，而 Hugo 的分页页 `.Permalink` 始终是列表首页地址。

同时发现几处会干扰规范信号的次要问题：

1. Hugo 生成的分页别名页（`/posts/page/1/` 等 112 个）是 200 + meta refresh 的重复页，且没有 noindex。
2. `/404.html` 带 `index, follow` 与自指 canonical，可能被当成有效页面收录。
3. `/search/` 这类站内搜索结果页可索引且被提交进 sitemap。
4. `content/assets/mapboxgl/mapboxgl.md`（0 字节、无引用）生成了空页面 `/assets/mapboxgl/mapboxgl/`
   和列表页 `/assets/`，后者还与 Hugo 资源目录 `/assets/css`、`/assets/js` 混在同一路径。
5. `static/laxedge/index.html` 是独立静态页，没有 canonical。
6. 语言只有 `zh` 一种，无 hreflang，不存在 hreflang 与 canonical 冲突。

## 实施内容

| 文件 | 改动 |
|---|---|
| `layouts/_partials/canonical.html`（新增） | canonical 唯一来源：显式 `canonicalURL` 优先；分页列表页（section/term 且真正调用 `.Paginate`）自指；其余用 `.Permalink` |
| `layouts/_partials/head.html` | canonical 改为调用上述 partial；404 不发 canonical；404 输出 `noindex` |
| `layouts/_partials/templates/opengraph.html`（新增覆盖） | 仅把 `og:url` 换成 canonical，保证与 canonical 同步 |
| `layouts/alias.html`（新增） | Hugo 别名页（`*/page/1/`）输出 `noindex, follow` |
| `layouts/sitemap.xml`（新增） | 过滤 `robotsNoIndex: true` 的页面，sitemap 只保留可索引且自指 canonical 的 URL |
| `content/search/index.md` | 增加 `robotsNoIndex: true` |
| `content/assets/mapboxgl/mapboxgl.md` | 删除（0 字节、无引用，产生空页面与 `/assets/` 列表页） |
| `static/laxedge/index.html` | 补自指 canonical |

## 明确不改的部分

- 根目录 `CNAME`：GitHub Pages 自定义域名依赖它，移动到 `static/` 有丢失域名风险。
- `https://jinyu.cool/index.html` 这类 `.html` 变体：GitHub Pages 无法配置 301，
  只保留 canonical 收敛；如后续需要强制 301，需在前面加 Cloudflare 规则（见验证清单）。
- `assets/js/fastsearch.js` 的现有未提交改动与本计划无关，未触碰。

## 验收标准

1. `/posts/page/2/` 的 canonical 等于自身，`og:url` 一致。
2. `/posts/`、`/tags/x/` 第 1 页 canonical 仍为自身。
3. `/search/`、`/404.html`、`*/page/1/` 均为 noindex；`/404.html` 无 canonical。
4. sitemap 中不再出现 `/search/`、`/assets/`，所有 URL 以 `/` 结尾且为 https 绝对地址。
5. 首页唯一 canonical 为 `https://jinyu.cool/`。
