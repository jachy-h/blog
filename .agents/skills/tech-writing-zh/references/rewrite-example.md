# 改稿示例：从多线草稿到单线文章

示例主题：**为什么 Node.js 服务在 Docker 里内存不释放**。这是一份真实写作中常见的多线草稿，下面标出问题、给出重排。

## 一、草稿

> Node.js 的内存管理一直是个麻烦事。V8 使用分代垃圾回收，新生代用 Scavenge，老生代用 Mark-Compact。Docker 默认没有内存限制，但 Kubernetes 里一般会设 limit，超过就会被 OOMKilled。
>
> 我们线上用的是 Node 16，`--max-old-space-size` 设成 1024，容器 limit 是 1.5G。有次监控报警，RSS 一直涨到 1.4G 也不回落，重启就好了。
>
> 顺便说一下，`process.memoryUsage()` 的 `rss` 和 `heapUsed` 经常差很多，因为 Buffer 和外部内存不算在 V8 堆里。另外 glibc 的 malloc 也会缓存内存不还给操作系统。
>
> 还有一个坑：Docker 的 `-m` 限制发生在 cgroup 层面，容器里的 `free -m` 看到的还是宿主机的内存。所以判断有没有超限不能看 `free`。
>
> 修复办法是用 `--max-old-space-size` 控制堆大小，或者升级到 Node 18 用 cgroup 感知。也可以定期重启。
>
> 顺带一提，PM2 的 cluster 模式会让每个 worker 都占一份内存，所以实例数也要算清楚。
>
> 总之，Node 内存问题要综合看 V8、容器和部署方式。

## 二、诊断

把草稿的节点列出来，会发现它其实有四个话题：

1. V8 分代垃圾回收机制
2. 线上案例：RSS 不回落
3. 外部内存、glibc 缓存、cgroup 可见性（三个并列的排查点）
4. 修复选项与 PM2 部署建议

这些点之间不是依赖关系，而是并列关系。读者读完不知道主线是「机制」还是「排查」还是「修复」。这是典型的星状结构，外加两处旁支（PM2、`free -m`）。

结尾「要综合看」是四线并存的直接证据：一篇文章如果有四个「总之」，就等于没有结论。

## 三、选主线

问：读者要走到哪个终点，必须经过哪几步？

终点定为一个可执行的判断：**看到 RSS 不回落时，先确认它是不是真的泄漏**。

必经节点只有四个：

1. 现象：RSS 涨到接近 limit 不回落，重启恢复。
2. 区分：RSS 高不等于 V8 堆泄漏，先看 `heapUsed`。
3. 解释：为什么 RSS 会高于堆——外部内存与分配器缓存。
4. 动作：按这个判断决定是调堆参数、调 limit，还是查真正的泄漏。

V8 分代回收、cgroup 可见性、PM2 实例数都移出主线：

- 分代回收 → 讲「怎么读堆快照」时才需要，另起一篇；
- cgroup 可见性 → 属于「limit 怎么设」，另起一篇；
- PM2 → 部署话题，另起一篇。

## 四、重排后的提纲

```
入口：一个具体的报警现象
  ↓
第 1 步：RSS 高 ≠ 堆泄漏（给出两个指标）
  ↓
第 2 步：RSS 高于堆的三个来源（外部内存 / 分配器缓存 / 碎片）
  ↓
第 3 步：一次最小验证（采样对比，判断是否持续增长）
  ↓
第 4 步：按结论分支行动（调参 / 调 limit / 查泄漏）
  ↓
出口：回到开头那个报警，说明现在该怎么处理
```

只有四步，每一步都用上一步的结论。第 2 步不需要读者知道 V8 分代细节；第 3 步的验证方法直接来自第 2 步列出的来源。

## 五、改写片段

多线草稿的开头是机制介绍，读者不知道自己要解决什么。单线版本把现象放在入口：

> 上周监控报警：一个 Node 服务的 RSS 涨到 1.4G，接近容器 1.5G 的 limit，但重启后立刻回落。这类现象通常被叫作「内存泄漏」，不过它有一半的概率不是。
>
> 这篇文章只回答一个问题：RSS 不回落时，怎么判断它是不是 V8 堆泄漏。判断完，你会在三种处理方式里选一种，而不是先改参数再观察。

第 2 步只做一件事——把两个指标分开：

> 先看 `process.memoryUsage()` 的两个数：`rss` 是进程向操作系统要到的全部内存，`heapUsed` 是 V8 堆里活着的对象。RSS 高而 `heapUsed` 平稳，说明内存不在堆里，泄漏的方向就变了。

这里不展开分代回收。读者此时不需要知道对象在新生代还是老生代，只需要知道「堆」和「非堆」是两回事。

第 3 步的验证方法接着第 2 步：

> 既然可疑区域不在堆里，验证就围绕 RSS 做：每 10 秒采一次 `rss`，跑 30 分钟。持续单调上升，才需要继续查；涨到某个平台期后走平，多半是分配器缓存，属于正常行为。

每一步都能从上一段直接推出来，不需要回看。
