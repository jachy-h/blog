# 中文技术写作：单线结构

技术写作的评价标准不是艺术性，而是表达是否清楚明白。它不需要华丽词藻、巧妙比喻和深刻感悟，只需要把问题说清楚。而问题能否说清楚，首先取决于思想是否清楚。

思想清楚落到文本上，表现为一个可检验的结构要求：**单线结构**。

## 什么是单线结构

一篇文章只说一件事，按线性顺序叙述，由浅入深、循序渐进、层层递进。

把它想成一个只有一条路线的景区：从入口到出口，跟着箭头走，就能看到全部景观。如果同时给出几条路线，读者会犹豫选哪条、担心错过什么；如果路线还互相交叉，读者必然会串线。

判定方法：把各节标题按顺序连起来读。它应该像一份步骤清单，后一步只用到前一步已经交代的内容。任何一节拿掉，后面的线就断了。

## 三条硬规则

1. **一篇一点。** 一篇文章只解决一个问题，或只证明一个结论。出现第二个问题时，另起一篇。
2. **线性推进。** 每一步建立在上一段已经交代的内容上。不要求读者回看，不要求读者跳读，不同时推进两条论证。
3. **有入口也有出口。** 开头交代起点和终点：这篇要解决什么，读完能知道什么、能做什么。结尾回到同一条线，停在终点，不要另开新话题收尾。

## 工作流程

1. **先写网，再理线。** 把所有想说的点写成无序清单，允许发散。人脑本来就是网状的，这一步不用克制。
2. **选一条主线。** 问自己：读者要走到哪个终点，必须经过哪几步？只保留必经节点。
3. **排序。** 把节点排成有依赖关系的序列，前一步的输出是后一步的输入。顺序不对时，先调整节点位置，不要靠过渡句硬接。
4. **砍旁支。** 不在主线上的内容，另起一篇、放进脚注，或直接删掉。不要为了显得完整而塞进去。
5. **逐节点写。** 一处只讲一个点，讲透再走。每节第一句说明这一节在整条线的哪个位置。
6. **回读验证。** 只看标题和每节第一句，能否独立走完全程。凡是需要往回翻的地方，就是断点。

## 复杂问题：拆，不要压

多个并列因素（星状）、多层子问题（层次结构）都真实存在，但不能硬塞进一篇。做法是拆成系列：

- 每篇保持单线，只讲一个点，并把这个点讲透；
- 篇与篇之间用一句话衔接：「上一篇讲了 X，这篇讲 Y」；
- 宁可三篇各讲透一点，不要一篇覆盖三点、每点都浮在表面。

拆篇不是逃避，是让每篇文章自己成立。

## 结构病害与对应改法

| 症状 | 判断 | 改法 |
| --- | --- | --- |
| 并列很多节，彼此不依赖 | 星状铺开 | 拆成系列，或只保留主线上的那一个 |
| 一节里同时推进两条论证 | 双线交叉 | 选一条，另一条另起一节或另起一篇 |
| 概念讲到一半跳进实现细节，又跳回来 | 层次错位 | 按「是什么 → 为什么 → 怎么做」重排 |
| 用「另外」「顺便说一下」「还有一点」接出的段落 | 旁支 | 移出正文，另起一篇或删除 |
| 读第五节必须先记住第三节的术语 | 依赖跨度过大 | 补一步桥接，或把该术语前移 |
| 开头连写几段背景和历史，迟迟不说要解决什么 | 入口缺失 | 第一段就给问题和终点，背景挪到需要它的位置 |
| 结尾突然提出新问题或宏大展望 | 出口偏移 | 收束到开头的终点，新问题另起一篇 |

## 与语言润色的分工

本技能只管结构。句子层面的空话、套话、模板化表达，交给 `humanizer-zh`。

结构不对时不要用润色掩盖：先重排，再润色。反过来，结构已经清楚的文章不必为了「有文采」加比喻和排比。

## 输出约定

- **给主题**：先交付一条线的提纲（5～8 个节点，标明起点和终点），确认后再写正文。不要一上来就铺开全文。
- **给草稿**：先判断是单线还是多线，指出断点、旁支和层次错位，给出重排后的提纲，再改正文。不要只改句子。
- **给文档**：保留原有的命令、路径、版本号和操作顺序；结构调整不能改变事实。
- 不为了显得完整而增加用户没要求的小节，不虚构数据、来源和实测结果。

## 自检清单

写完逐条过一遍，有一项不过就改结构，不要放过：

- [ ] 能用一句话说出这篇文章唯一要讲的事。
- [ ] 标题连起来是一条可执行的路线，不是一组并列话题。
- [ ] 每一节只依赖它前面已经出现的内容。
- [ ] 没有需要读者回看才能读懂的地方。
- [ ] 没有「另外」「顺便」引出的旁支。
- [ ] 开头给了终点，结尾停在同一终点。
- [ ] 每个点都讲透了，而不只是提到了。
- [ ] 如果拆成多篇会更好，已经拆了。
